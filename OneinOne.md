## Что это

G-Fone F1 — концепт защищённого смартфона для **технарей** и энтузиастов приватности, ремонтопригодности и «железа без компромиссов». Это не продукт, не оферта и не инструкция к производству. Просто инженерная идея, выложенная в открытый доступ для обсуждения, критики и улучшения.

Целевая аудитория — люди, которым надоело, что их данные читают все подряд, и которые готовы жить с нишевым tool-девайсом. Не масс-маркет. Не enterprise.

## Основные характеристики

- **SoC:** MediaTek Dimensity 9600 Pro, 2 нм, TSMC N2P. Конфигурация 2+3+3: 2× C2-Ultra до 4.55 ГГц, 3× C2-Pro до 4.35 ГГц, 3× C2-Pro до 3.1 ГГц. 34.5 МБ кэша. LPDDR6 + UFS 5.0. (*projected / assumption — при фиксации BOM нужна ссылка на вендора; анонс/сроки не считать фактом без источника.*)
- **Память (только внутренняя):** 16 ГБ LPDDR6 + **256 ГБ UFS 5.0** (слота microSD нет).
- **Экран:** 6.77" LTPS IPS QHD (осознанный IPS, не позиционируется как «AMOLED-флагман»). Видео до 2K.
- **АКБ:** 5S1P, 5 × 2500 мА·ч, **номинал пакета ~18.5 В** (5×3.7), **полный заряд до ~21 В** (5×4.2). Энергия **46.25 Вт·ч** (расчёт). Призматический Li-polymer. Крепление **X-Cross** (металлический крестик — **механика**, не IC). Battery Board с **BMS**: **активная балансировка** 5S, защита OV/UV/OT/OC/short. BMS предпочтительно на **документируемом контроллере** (семейство TI BQ / аналог с datasheet и драйверами, выбор ODM); X-Cross ≠ чип BMS. Мониторинг: V каждой ячейки; **NTC на каждой** из 5; **шунт** тока пакета. (Схема 5S1P серийно применяется в дронах/RC; для смартфона нетипична.) Сертификация пакета (IEC 62133, UN38.3 и т.п.) — **ODM gate**.
- **Зарядка / БП:** до 80 Вт **проводная**, КПД ≈ 95% (~76 Вт до батареи при идеальных условиях). Тракт рассчитан на **5S1P**: номинал ~18.5 В, **верх ~21 В** — нужен **USB PD PPS** (или аналог) с диапазоном до ~21 В; фиксированный профиль 20 В PD **не** покрывает полный CV. 0–80% ≈ 29 мин; 0–100% ≈ 45–50 мин при выключенном экране — **расчётный target / оценка**, не лабораторное измерение; дальше сказывается CV-фаза. При ~80 Вт в пакет 46.25 Вт·ч это около **1.6C** — **агрессивно** для призматических ячеек телефонного класса: **щадящий режим по умолчанию** (напр. 40–50 Вт) и target циклового ресурса (напр. 80% ёмкости через N циклов) — **TBD с ODM**. **Беспроводной зарядки нет.** Тракт зарядки — **не** single-cell 3.7 В.
- **Почему без wireless:**
  1. **КПД** заметно ниже проводного (типично ~60–75% wall-to-battery vs ~90–95% у 80 Вт wire).
  2. **Локальный нагрев** в зоне катушки нежелателен для пакета 5S1P и BMS.
  3. Дополнительно: ЭМП катушки ухудшает работу магнитометра (в корпусе 7075-T6 + металлический X-Cross компас и так сложный).
- **Связь / слоты:** **механических слотов SIM и microSD нет**. Сотовая связь — **eSIM only** (до 2 профилей — по ODM). BT к внешним спутниковым терминалам. Прямой спутниковый модем не заявляется.
- **Хранилище:** внутреннее **только** 256 ГБ UFS 5.0; расширение — **USB Host** (любой объём). В комплекте **USB → SATA с питанием** (см. USB Host Storage).
- **Цена:** €3200 (ориентир для нишевого флагмана / tool-девайса).

### Почему нет microSD?
- **Меньше точек отказа:** нет лотка, контактов и канала влаги — плюс к IP69/IP69K и надёжности корпуса. Это аргумент **надёжности/герметики**, не «легче чинить mainboard».
- **Гибкость через стандарты (USB)**, а не проприетарный слот карты.
- **256 ГБ UFS 5.0** внутри; объём «снаружи» выбирает пользователь.
- При отказе UFS — путь через **DualBIOS** (уведомление + boot с внешнего диска, если образ записан и политика AVB соблюдена). Без DualBIOS/образа отказ UFS — сервисный сценарий, не magic unbrick.

### USB Host Storage: гибкость на стороне пользователя
Слота microSD **нет** — пользователь сам выбирает внешний SSD/HDD через USB.

- **Объём под контролем пользователя** (пример: Kingston 2 ТБ или любой USB SSD).
- **Задел на будущее:** USB 3.2 / открытые стандарты, не проприетарный слот.
- Данные **не привязаны** к внутреннему UFS (бэкап, «толстый» архив, repairability данных).
- **2.5″ SSD:** по возможности питание от **USB-C / PD порта телефона** или комплектного адаптера **без** отдельной «стены 12 В»; если мосту не хватает тока — внешнее 5 В от адаптера в комплекте.
- **3.5″ HDD:** нужны **отдельные 12 В** от адаптера; **не** от порта телефона и **не** из бюджета 80 Вт charge path. Сценарий — стол/лаборатория, не «в кармане».
- **Signed / authenticated storage *(политика, concept)*:** для чувствительных томов — опциональная проверка подписи / политик доступа к внешнему носителю, согласованная с AVB external-boot (не «любой диск = доверенный»). Не обязательный маркетинг USB-IF; design intent для технарей.
- В комплекте: адаптер **USB → SATA с питанием** под эти правила.
- Подключи USB SSD: **G-Fone F1 — инструмент, а не бытовой гаджет.**

### DualBIOS *(инженерный узел)*

**Проблема:** производственный **Boot ROM в SoC** обычно **не** умеет сам грузиться с USB-накопителя. Отдельный «запасной носитель» сам по себе не передаёт управление CPU — нужен **вторичный loader**, который SoC **принимает** по известной цепочке.

**Модель (design intent):**
1. **Boot ROM в SoC** (неизменяемый, зашит в процессоре) — всегда первый этап.
2. Нормальный путь: primary boot media = **UFS 5.0** (loader + AVB + ОС).
3. **DualBIOS-чип** — отдельный чип со **своей** boot-прошивкой (типично SPI NOR / аналог), видимый SoC как **fallback boot source** после провала UFS (конкретный mux/strap/порядок опроса — **ODM + SoC boot policy**).
4. DualBIOS **не** «магически грузит USB»: он поднимает **минимальный secondary loader**, который:
   - **уведомляет** об отказе UFS;
   - при наличии совместимого образа на USB Host — предлагает / продолжает загрузку Android **только** в рамках политики ниже.

**Verified Boot / AVB (обязательно для threat model):**
- Загрузка с внешнего диска **не** «любой диск = root».
- Допустимые режимы *(выбор ODM, описать в UX)*:
  - **A:** внешний образ **подписан ключом пользователя** (user-owned keys) и проверяется AVB/аналогом; или
  - **B:** проверка **отключаема**, но только с **явным предупреждением** (и по возможности физическим подтверждением) — иначе подменённый диск = точка атаки.
- Без одной из этих политик DualBIOS **не** позиционируется как privacy-safe recovery.

**UX уведомления при мёртвом экране:**
- Если панель / UFS-зависимый bring-up не поднимается: индикация через **RGB SMD / SK6812** и/или **USB device-side status** (не полагаться только на дисплей).

**Статус:** инженерный узел; требует валидации boot ROM / fuse policy MediaTek, secure boot и UX. Не unbrick «из воздуха».

### eSIM: Privacy-First Control
Кастомная eSIM-логика с ограничениями **на стороне userspace/OS**:

- Пользователь может **только активировать / деактивировать** профили.
- Удаление, правка профиля и телеметрия **заблокированы** без **явного** согласия пользователя.
- Все операции **логируются локально** (журнал на стороне ОС).
- **eSIM полностью независим от экосистем** Apple/Google/OEM (магазины/lock-in).

**Честно про baseband / eUICC:**
- Профили идут через eUICC / SM-DP+ / OTA; **прошивка модема и eUICC закрыты** почти у всех поставщиков.
- Блокировка на уровне ОС — **политика**, не гарантия отсутствия действий на стороне модема/eUICC.
- «Неизменяемый журнал» в userspace без **аппаратного якоря** (TEE / secure element + hash-chain) — усиленный log, не математическая / крипто-неизменяемость.
- См. **Threat model**.

*Устройство служит пользователю, а не операторам — в пределах контролируемого софта и RF-path.*

### Почему 2500 мА·ч — это не опечатка

5S1P — это 5 последовательно соединённых ячеек по 2500 мА·ч. Напряжение пакета номинально ~18.5 В, full ~21 В. Энергия 46.25 Вт·ч. Это **≈3×** больше (точно **2,9800257731958×**), чем у Galaxy S24 (типичная ёмкость **4000 мА·ч**, официально **15,52 Вт·ч**). Эквивалент при 3.7 В — **12 500 мА·ч**. Это **эквивалентный расчёт**, не номинал одной банки и не marketing mAh «как у single-cell».

### X-Cross
Внутренняя **металлическая деталь в виде крестика**: удерживает и фиксирует призматические ячейки 5S1P на Battery Board. Это **механика**, не электроника BMS.

### BMS и балансировка (5S1P)
**Активная балансировка** — обязательный базовый уровень. Пассивная (bleed) греет pack и хуже по КПД. Мониторинг: V каждой ячейки; **датчики температуры АКБ** (NTC) на каждой из 5; **шунт** тока пакета. Защита OV/UV/OT/OC/short. Предпочтительно **известный/документируемый** BMS IC (TI BQ-класс или аналог), а не «чёрный модуль без datasheet».

### Комплект
- **Напальчники** из ткани: 7075-T6 сильно отводит тепло — безопасность пальцев (холод/перегрев) при голом корпусе, **не** «защита от порезов».
- **Адаптер USB → SATA с питанием** (правила 2.5″ / 3.5″ — выше).
- Чехол-рамка с хватом + силиконовые колпаки камер (средняя цена, антицарапалка).

### Питание / PMIC
Гибрид: HV front-end на **18.5 В номинал / до ~21 В full**; **дроссель фильтра в телефоне**; multiphase buck на hot rails SoC; companion для остальных доменов. Partial PMIC integration *(концепт / ODM)*.

### Open-source HDR Stacking *(userspace, GPLv3)*
- Съёмка **серии кадров** (разные экспозиции / burst) и **объединение в процессе** на устройстве.
- Полностью в **userspace**, лицензия **GPLv3** (совместимо с userspace G-Fone; **не** смешивается с ядром GPLv2).
- Алгоритмы открытые (alignment + merge / exposure fusion и аналоги) — **без** проприетарного ISP-AI и **без** облака.
- Цель: контролируемый динамический диапазон там, где binning и один кадр не тянут, без передачи снимков вендору.

## Уникальные аппаратные решения

### SMD = **Stop Meta Data** (не surface-mount device) — сдвоенная кнопка

Одна физическая клавиша, **два независимых сегмента** (разделение влево / вправо):

| Сегмент | Функция | Аппаратно |
|--------|---------|-----------|
| **Левый (основной)** | Stop Meta Data | **Обрывает питание** камер, микрофонов и акселерометра (не софтовый mute) |
| **Правый (отдельный)** | RF kill L1 / L2 | См. уровни ниже |

**Правый сегмент — уровни RF kill:**
1. **Baseline (сейчас / обязательно):** hardware **RF path kill** — обрыв антенных трактов → нет TX/RX в эфир. Модем **остаётся в SoC** (Dimensity — интегрированный baseband); домен может оставаться под питанием; **DMA к RAM возможен**. Kill **≠** изоляция модема от памяти и **≠** «модем вырезан из SoC».
2. **ODM-цель (если SoC/PMIC даёт отдельный power rail baseband/eUICC):** hardware **rail kill** — снятие питания с того домена, который реально выведен отдельно. Всё ещё **не** доказательство «idle внутри каждого транзистора», но сильнее path-only.
3. Если отдельного rail **нет** (типично для интегрированного модема) — в спецификации честно остаётся только уровень 1; уровень 2 **не** обещается маркетингом.

Индикация: многорежимный RGB (Privacy / Charge / Thermal Hue) на SMD 4020 + линии SK6812.

Физическое «лево/право» — относительно нормальной ориентации корпуса (экран к пользователю, антенна сверху); финальная раскладка — CAD.

### Easter egg: Mindustry load arrows
Когда открываешь **Mindustry**, в момент загрузки игры подсветка (SMD + SK6812) повторяет анимацию загрузочных стрелок (из середины горизонтали) в том же свете/цвете, что на экране. Не привязано к boot устройства.

## Threat model (честные границы)

**Защищаем (в пределах концепта):**
- Локальные данные: FBE; отсутствие GApps по умолчанию; минимум вендорской телеметрии в userspace.
- Сенсоры: **левый SMD** — аппаратное снятие питания с камер / мик / акселерометра.
- Радиоизлучение: **правый SMD L1** — аппаратный RF path kill; **L2 rail** — только если ODM подтвердил отдельный rail.
- eSIM UX: activate/deactivate only, локальный log, без lock-in экосистем магазинов.
- USB Host + optional signed-storage policy; **DualBIOS** fallback **только** с AVB user-keys или explicit disable+warning.
- **Локальный HDR Stacking** без облака и без проприетарного generative AI.
- Железо: glue-free 7075 intent, документируемые узлы (BMS class, CERN-OHL).

**Не гарантируем:**
- Отсутствие закладок / недокументированного поведения в **SoC и baseband** (модем интегрирован; полный аудит кремния нереалистичен — **глобальное** ограничение).
- **Отсутствие DMA / работы модема** при path-only RF kill.
- Rail kill, если отдельного power domain в SoC/PMIC нет.
- Действия eUICC/модема вне контроля ОС.
- Автоboot с внешнего диска без записанного образа / без AVB-политики.
- Сертификацию АКБ «уже готово» (ODM gate).
- Крипто-неизменяемость журнала без TEE/SE.

Для технарей честная граница угроз убедительнее лозунга «полная приватность».
